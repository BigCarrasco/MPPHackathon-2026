# Azure App Service demo

## Recommended starting point

For an account without credits, start with **App Service on Linux, Free F1, using a code deployment**. The published F1 limits include 60 CPU minutes per day, 1 GB RAM and 1 GB storage. It is intended for trials and learning and has no SLA. Do not assume uninterrupted availability for an evaluation.

Select F1 explicitly. If the region or subscription does not offer it, stop and review the alternatives instead of accepting a paid plan. A Basic plan is a separate spending decision. The current Node quickstart's CLI example can create a paid Premium plan, so do not run it unchanged.

Deploy the Node code directly on F1. The repository's Dockerfile is an alternative for a container-capable hosting plan, not this free code-deployment route.

## Environment and secrets

Set these in the Web App's environment settings:

- `HOST=0.0.0.0`
- `BARRA_DATA_DIR=/home/barra-data`
- `MPP_SECRET_KEY`: a random 32-byte hexadecimal secret.
- `MPP_RECIPIENT`: disposable Testnet recipient address.
- `TEMPO_TESTNET_PRIVATE_KEY`: funded disposable Testnet payer key.
- `DEMO_ACCESS_CODE`: at least 12 random characters, shared privately with evaluators.

Use Azure's supplied port. Do not expose the keys in GitHub, frontend code or the submission form. The server remains fixed to Tempo Testnet 42431.

`BARRA_DATA_DIR` keeps payment records outside the deployed application files. App Service's `/home` storage is the intended persistent location for this code deployment. The application still requires one process and one instance because its file store is not a shared database.

Avoid adding unrelated paid resources, a container registry, paid monitoring or a database for this F1 trial. Review Azure's resource summary and estimated cost before confirming creation.

## Verify before submission

1. Open the resulting HTTPS URL and confirm the English dashboard loads.
2. Check `/api/health`: `chainId` is 42431 and `realPayments` is false.
3. Call `/api/supplier/quote` without paying: expect HTTP 402 with a Payment challenge.
4. Enter the private demo code in the dashboard and generate a quote.
5. Verify the Testnet receipt, then repeat the request to check no second payment occurs.
6. Paste the service origin into the [hackathon form](https://mpp-hackathon.vercel.app/submit) and run its scan.

The F1 trial may become inactive and has daily CPU limits. Rehearse the full request shortly before presenting and confirm the public URL is reachable. If continuous availability is required, choose and budget a paid tier separately.

No Azure resources have been created or deployed by these instructions.
